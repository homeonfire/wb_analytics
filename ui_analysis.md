## 1. 📊 Dashboard (Главная страница)

### Что показывает
- **Stats Overview** (скрыт, `canView() = false`): Заказы сегодня vs вчера, выручка, остатки FBO
- **Sales Chart**: Двухосевой график — выручка (линия, ₽) + заказы (столбцы, шт) за 30 дней
- **Top Products Table**: Топ-5 товаров по выручке за 30 дней (кликабельные строки → переход к товару)

### Источники данных
- `order_raws` (заказы, выручка)
- `sale_raws` (выручка для графика и топа)
- `skus` → `sku_warehouse_stocks` (остатки FBO)

### ⚠️ Проблемы
1. **DashboardStatsOverview отключён** (`canView() = false`) — пользователь не видит ключевые метрики дня
2. **TopProductsTable**: N+1 запросы — для каждой из 5 строк делается отдельный `Product::where('nm_id', ...)->first()` × 3 раза (фото, название, URL)
3. **DashboardSalesChart**: Нет фильтра по периоду — хардкод 30 дней

### 💡 Рекомендации для нового UI
- **Включить Stats Overview** — это самая ценная информация для быстрого понимания ситуации
- **Добавить карточки**: Средний чек, Процент отмен, ДРР (доля рекламных расходов)
- **Добавить переключатель периода** на графике (7д / 14д / 30д / за месяц)
- **TopProducts**: предзагружать products через JOIN, а не поштучным lookup
- **Добавить сравнение с предыдущим периодом** (было/стало)
- **Добавить виджет «Проблемные товары»** — товары без остатков, с нулевой себестоимостью, с высоким ДРР

## 2. 🛍️ Товары (ProductResource)

### Таблица (Список)
| Колонка | Данные | Примечание |
|---------|--------|------------|
| Фото | `main_image_url` | Круглое превью |
| WB ID | `nm_id` | Поиск, сортировка, копирование |
| Артикул | `vendor_code` | Поиск |
| Заказы | `withCount('orders')` | Бейдж, зелёный/серый |
| Бренд | `brand` | Поиск |
| Название | `title` | Скрыто по умолчанию, лимит 30 |
| ABC | `abc_class` | Бейдж (A=зелёный, B=жёлтый, C=красный) |
| Маржа (30 дн) | `margin_30d` | Бейдж с цветом |
| Выручка (30 дн) | `revenue_30d` | Скрыта по умолчанию |
| Себестоимость | `cost_price` | **Редактируемое inline** (TextInputColumn) |
| FBO | Вычисляемое | Сумма `warehouseStocks.quantity` |
| ID | `id` | — |

### Фильтры
- Бренд (Select)
- Нет себестоимости (Toggle)
- Остаток на WB (Ternary: все/в наличии/закончились)
- Мои товары (Toggle — по текущему менеджеру)

### Bulk Actions
- Удаление
- Задать себестоимость для выбранных

### Форма (Создание/Редактирование)
3-колоночный layout:
- **Основная информация**: nm_id, vendor_code, brand, title, менеджеры (M2M select)
- **Финансы**: себестоимость
- **Фото**: FileUpload
- **Сезонность**: Repeater (start_month, end_month)

### Карточка товара (View / Infolist)
Мощная страница с 5 секциями:
1. **Карточка товара**: Фото, название, бренд, артикулы, менеджеры, ссылка на WB
2. **P&L Аналитика** (ProductPnLOverview): 6 Stats — Выручка, Заказы, Выкупы, % Выкупа, Остаток, Маржинальность
3. **Моделирование цены** (UnitEconomicsCalculator): Интерактивный калькулятор юнит-экономики с live-пересчётом
4. **Воронка продаж 30 дней** (ProductFunnelWidget): Визуализация воронки
5. **Детальная аналитика** (ProductAnalyticsTable): Таблица данных по дням
6. **Сезонность**: Repeater-просмотр периодов
7. **Relation Manager**: `SkuLogisticsRelationManager` — логистика по размерам

### ⚠️ Проблемы
1. **Колонка «Заказы»**: `withCount('orders')` считает ВСЕ заказы за ВСЕ время — нет периода
2. **Колонка FBO**: Вычисляемая через `getStateUsing` с eager load — неэффективна при большом количестве товаров
3. **Фильтр «Бренд»**: Загружает все бренды в память, при 10k+ товаров будет тормозить
4. **FileUpload для фото**: Бессмысленно — фото приходят с WB API, загрузка своего фото не имеет значения (WB его всё равно не покажет)
5. **UnitEconomicsCalculator**: Цена продажи (`sell_price`) — хардкод 3500₽ вместо реальной цены из `skus.price`

### 💡 Рекомендации
- **Заказы**: Показывать за последние 30 дней, либо за текущий месяц
- **FBO**: Рассчитывать через SQL subquery, а не через PHP
- **Калькулятор**: Подтягивать реальную цену продажи из `skus.price` (первый SKU)
- **Убрать FileUpload**: Фото всегда подтягиваются с WB, ручная загрузка бесполезна
- **Добавить**: Колонку «Скорость продаж» (шт/день за 14д) и «Дней до 0» (остаток / скорость)
- **Добавить**: Статус товара (в продаже / закончился / снят)
- **Карточка**: Добавить секцию «Рекламные кампании» (привязанные к этому nm_id)

## 3. 🚚 Логистика (LogisticsResource)

### Что показывает
Сводная таблица по товарам с полной цепочкой логистики:

| Колонка | Источник | Описание |
|---------|----------|----------|
| Фото | `products.main_image_url` | — |
| Товар | `title`, `brand`, `vendor_code` | Комбинированный |
| Фабрика | `sku_stocks.at_factory` | Сколько на фабрике |
| В пути с фабрики | `sku_stocks.in_transit_general` | Карго |
| Склад | `sku_stocks.stock_own` | Наш склад |
| В пути WB | `sku_stocks.in_transit_to_wb` | В пути на WB |
| На WB | `sku_warehouse_stocks.quantity` | FBO остаток |
| К клиенту | `sku_warehouse_stocks.in_way_to_client` | — |
| Ср.прод | Вычисляемое | Продажи за 30 дней / 30 |
| Обор. | Вычисляемое | Остаток / скорость (дней) |

### Виджет-шапка
`LogisticsStatsOverview` — 3 карточки:
- В производстве (Фабрика)
- Едет Карго
- Заморожено в пути (себестоимость × количество)

### Действия (Actions)
- **К товару**: Ссылка на карточку товара
- **Размеры**: Модальное окно с разбивкой по SKU

### Header Actions (Кнопки сверху)
- **Экспорт Excel**: Полная выгрузка логистики (LogisticsExport)
- **4 кнопки импорта**: Фабрика, В пути с фабрики, Склад, Путь WB — каждый импортирует из Excel в `sku_stocks`

### Фильтры
6 Min/Max фильтров по каждому числовому полю + фильтр по скорости продаж

### ⚠️ Проблемы
1. **Ср.прод и Обор.**: Для КАЖДОЙ строки делается отдельный запрос `$sku->sales()->count()` — это **N+1 на стероидах** (если 100 товаров × 3 SKU = 300 SQL-запросов)
2. **Фильтры**: Используют `whereRaw` с вложенными подзапросами — тяжёлые для PostgreSQL
3. **Обороачиваемость (Обор.)**: Сравнение string и int (`$state === '∞'` и `$state < 60`) — потенциальный баг с типами
4. **processImport**: `current(Sku::where()->get()->all())` — загружает ВСЮ коллекцию, берёт первый элемент. Нужно `->first()`

### 💡 Рекомендации
- **Скорость продаж**: Предрасчитывать в таблице `products` (поле `sales_speed_30d`) через CRON, а не считать на лету
- **Оборачиваемость**: Аналогично — хранить в `products` как `turnover_days`
- **Импорт**: Заменить `current(->get()->all())` на `->first()`
- **Добавить**: Колонку «Нужно заказать» (формула: скорость × lead_time - остаток)
- **Добавить**: Цветовую кодировку строк (красный = закончился, жёлтый = мало, зелёный = ок)

## 4. 📺 Реклама (AdvertCampaignResource)

### Что показывает
Таблица рекламных кампаний с агрегированными метриками:

| Колонка | Вычисление | Примечание |
|---------|-----------|------------|
| Товар (фото) | `product.main_image_url` | — |
| Кампания | `name`, `advert_id`, `type_name` | — |
| Статус | `status` | Бейдж с цветом |
| Показы | SUM(views) | С учётом фильтра периода |
| Клики | SUM(clicks) | — |
| CTR | clicks/views | Вычисляемое |
| В корзину | SUM(atbs) | — |
| Заказы | SUM(orders) | — |
| CPO | spend/orders | Вычисляемое |
| Заказы (руб) | SUM(sum_price) | — |
| Расход | SUM(spend) | Красный |
| ДРР | spend/revenue | Вычисляемое, зелёный/красный по порогу 20% |

### Фильтры
- **Период** (DatePicker from/until): Используется через `baseQuery` с `withAggregate` — **очень грамотная реализация**! При фильтрации пересчитываются все агрегаты
- **Статус**: Дефолт = Активна (9)
- **Мои РК**: Фильтрация по товарам текущего менеджера

### Relation Manager
`StatisticsRelationManager` — детализация по дням

### ⚠️ Проблемы
1. В целом — **одна из лучших реализаций** в проекте. Фильтр по периоду с baseQuery — отлично
2. **Без фильтра периода**: Показывает агрегат за ВСЕ ВРЕМЯ — может вводить в заблуждение
3. **ДРР порог**: Хардкод 20% — у разных категорий разные допустимые ДРР

### 💡 Рекомендации
- **Дефолтный период**: Сделать «Последние 7 дней» вместо «всё время»
- **Добавить**: ROAS (Return on Ad Spend) = revenue / spend
- **Добавить**: Группировку по типу кампании (Поиск, Авто, Каталог)
- **Добавить**: Общий итог внизу таблицы (сумма расходов, заказов, ДРР)
- **Добавить**: Графики (расход/заказы по дням) на странице кампании

## 6. 👤 Мои товары (MyProducts Page)

| Колонка | Описание |
|---------|----------|

| % Выкупа | **ЗАГЛУШКА**: `rand(30, 85)` (!!) |
| Остатки | FBO |
| Заказы (Ф/П) | Кастомный ViewColumn с прогресс-баром |
| Продажи (Ф/П) | Аналогично |
| Маржа (Ф/П) | Выручка - (количество × себестоимость) |

- **Header**: MyPersonalStatsWidget (заказы, выкупы, сумма за месяц)

### ⚠️ Проблемы
1. **% Выкупа = `rand(30, 85)`** — **КРИТИЧЕСКИЙ БАГ!** Показывает случайные числа вместо реальных данных

- **СРОЧНО**: Заменить `rand(30, 85)` на реальный расчёт из `product_analytics` (orders_count vs buyouts_count)
- **СРОЧНО**: Убрать хардкод СПП 0.75, брать из реальных данных (или дать возможность задать)
- **Добавить `margin_plan`** в миграцию `product_plans`, либо рассчитывать план маржи автоматически
- **Добавить**: Графики план/факт по месяцам

## 10-11. 📥 Импорт себестоимости / Привязка товаров

### Что показывают
Простые формы загрузки Excel:
- **ImportCostPrice**: Столбец A = nm_id, Столбец B = цена → обновляет `products.cost_price`

1. **Нет превью**: Пользователь не видит, какие данные будут загружены, до нажатия «Импорт»

3. **ImportCostPrice**: В описании написано «Столбец D», в коде — `$row[1]` (столбец B) — противоречие

### 💡 Рекомендации
- **Добавить превью**: Показать первые 5 строк файла перед импортом
- **Добавить лог**: Список обновлённых / не найденных артикулов
- **Объединить** обе страницы в одну «Импорт данных» с табами

## 12. Виджеты на карточке товара

### ProductPnLOverview (6 Stats)
- Выручка, Заказы, Выкупы, % Выкупа (из воронки), Остаток, Маржинальность
- **Данные**: `sale_raws`, `order_raws`, `product_analytics`, `sku_stocks` + `sku_warehouse_stocks`
- **Проблема**: Все данные за ВСЕ время — нет фильтра по периоду

### ProductSalesChart (6 datasets)
- Выручка (₽, линия), Сумма заказов (₽, пунктир, скрыта), Выкупы (шт, столбцы), Заказы (шт, линия), % выкупа (линия)
- **3 оси Y**: Рубли, Штуки, Проценты
- **Отлично** реализовано визуально — Chart.js с кастомными настройками
- **Проблема**: Фиксированный период 30 дней

### UnitEconomicsCalculator
- Интерактивный калькулятор с live-пересчётом (debounce 500ms)
- Формула: `Прибыль = Цена - Себестоимость - Комиссия - Налог - (Логистика с учётом возвратов)`
- **Отлично**: Учитывает обратную логистику через формулу `(Логистика + Возврат × (1 - %Выкупа)) / %Выкупа`
- **Проблема**: Цена хардкод 3500₽

### ProductFunnelWidget
- Визуализация воронки продаж за 30 дней
- `product_analytics` — SUM по полям open_card_count, add_to_cart_count, orders_count, buyouts_count
