# Техническое задание (ТЗ) на рефакторинг проекта WB-App

## 1. Цель проекта
Перенос существующего проекта WB-App с фреймворка Filament на кастомную структуру с использованием связки **Laravel (Backend)** и **Vue.js (Frontend)**. Цель — создание красивого, быстрого и интуитивно понятного пользовательского интерфейса, а также оптимизация архитектуры, при сохранении текущей базы данных, исторических данных и интеграций с Wildberries.

## 2. Обязательный этап (Onboarding)
Перед началом любой разработки в новом проекте, разработчик **обязан досконально изучить 3 базовых документа**, составленных на основе оригинального проекта:
1. `project_documentation.md` — общая архитектура, связи в БД и логика работы команд.
2. `wb_integrations_reference.md` — исчерпывающее описание работы с API Wildberries (эндпоинты, маппинг полей, upsert-ключи, rate-limits).
3. `ui_analysis.md` — детальный разбор старого UI, включая список критических багов (например, хардкод % выкупа) и приоритетных улучшений для нового фронтенда.

## 3. Технологический стек
*   **Backend:** Laravel (существующий или новый чистый инстанс).
*   **Frontend:** Vue.js 3 (интегрированный внутрь Laravel). Рекомендуется использование **Inertia.js** для бесшовной связи Laravel и Vue без необходимости писать полноценный REST API, либо связка Laravel API + Vue Router (на усмотрение команды, но Inertia.js предпочтительнее для монолита).
*   **База данных:** PostgreSQL.
*   **Стилизация фронтенда:** Tailwind CSS (опционально, но стандарт де-факто для современных Vue-интерфейсов) + современные UI-компоненты.

## 4. Требования к Базе Данных (КРИТИЧЕСКИ ВАЖНО)
1. **Никаких миграций, изменяющих схему БД.** Проект будет подключен к **уже существующей и наполненной базе данных**.
2. Имена таблиц, колонок, индексы и связи (Foreign Keys) остаются неизменными.
3. Модели Eloquent должны быть перенесены/настроены таким образом, чтобы точно соответствовать существующей структуре БД (описано в `project_documentation.md`).
4. При развертывании проекта скрипты миграций не должны ломать текущую структуру.

## 5. Мультитенантность (Multi-tenancy)
Одной из ключевых фич системы является поддержка множества магазинов.
1. Все данные (заказы, продажи, товары, реклама) строго привязаны к конкретному `store_id`.
2. **В новом UI необходимо реализовать глобальный переключатель магазина** (если у пользователя доступ к нескольким магазинам).
3. При выборке данных Backend всегда должен накладывать глобальный scope или явное условие `where('store_id', $currentStoreId)` в соответствии с правами пользователя.
4. **Контроль доступа (RBAC):** Super Admin видит все магазины, Manager — только те, которые ему назначены (связь `store_user`), и только те товары, которые к нему привязаны (связь `product_user`).

## 6. Требования к Backend (Laravel)
1. **Синхронизация данных WB:** Команды из папки `App\Console\Commands\` (синхронизация заказов, продаж, контента, рекламы, остатков) переносятся в новый проект **без изменения бизнес-логики**. Вся логика upsert-запросов и обхода лимитов описана в `wb_integrations_reference.md`.
2. **Оптимизация N+1:** Исправить узкие места старой системы (подробно описаны в `ui_analysis.md`), такие как N+1 запросы при подсчете остатков FBO, скорости продаж и выборке топ-товаров.
3. **Расчеты:** Перенести расчет ABC-анализа (`products:calculate-abc`) и юнит-экономики на бэкенд, чтобы отдавать фронтенду уже готовые цифры, а не заставлять Vue считать это в браузере (кроме интерактивного калькулятора).

## 7. Требования к Frontend (Vue.js)
От старого интерфейса (Filament) полностью отказываемся в пользу гибкого кастомного UI.

**Ключевые страницы для реализации (согласно `ui_analysis.md`):**
1. **Главный дашборд (Dashboard):**
   *   Ключевые метрики дня (Заказы, Выручка, Остатки) с динамикой к предыдущему дню.
   *   Двухосевой график продаж и заказов с возможностью выбора периода (7д, 14д, 30д, месяц).
   *   Топ-5 товаров по выручке.
2. **Каталог товаров:**
   *   Быстрая таблица товаров с бейджами (ABC класс, маржа, остаток FBO).
   *   Избежать загрузки 10 000+ брендов в фильтры (использовать асинхронный поиск).
3. **Карточка товара (Детализация):**
   *   Сводная аналитика (P&L, график заказов).
   *   Исправление критического бага старого UI: **% выкупа должен рассчитываться по реальным данным воронки (`product_analytics`), а не генерироваться функцией `rand()`!**
   *   Интерактивный калькулятор Юнит-экономики (с предзаполненной реальной ценой продажи, а не хардкодом 3500₽).
4. **Остатки и Логистика:**
   *   Объединить экраны "Аналитика по товарам" и "Логистика" в один понятный интерфейс.
   *   Вывести сводные метрики ("замороженные деньги в пути", "на фабрике", "едет карго").
5. **Реклама (Внутренняя и Внешняя):**
   *   Отображение кампаний с расчетом ДРР, CPO и ROI.
   *   Учет статуса активности РК.
6. **Раздел Менеджера (Мои товары):**
   *   Мониторинг выполнения плана продаж (факт/план с прогресс-барами).
7. **Инструменты (Импорт):**
   *   Загрузка себестоимости и привязок менеджеров через Excel.
   *   Обязательно добавить окно предпросмотра (Preview) загружаемых данных перед записью в БД, чего не было в старой версии.

## 8. Порядок выполнения работ
1. **Инициализация:** Поднятие чистого Laravel + Vue.js (рекомендуется Laravel Breeze/Jetstream с Inertia Vue или ручная настройка).
2. **Настройка БД:** Настройка соединения с существующей БД, перенос моделей Eloquent и связей без миграций.
3. **Бэкенд ядро:** Перенос Cron-команд, логики мультитенантности, системы авторизации.
4. **API / Контроллеры:** Создание эндпоинтов для передачи данных во Vue-компоненты.
5. **Фронтенд:** Поэтапная разработка экранов (начиная с Layout, Dashboard и списка Товаров), внедрение красивых чартов (например, Chart.js или ApexCharts) и UI-элементов.
6. **Оптимизация и Тестирование:** Проверка устранения багов из `ui_analysis.md`, тестирование работы с большими объемами исторических данных.
